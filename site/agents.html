Shrooms Agents

Your coding agents, on your own machines, from your phone.

Why it belongs next to shrooms

You leave Claude Code working on the laptop, or on a box at home, and walk away. Then it stops to ask whether it may run something — and you are not there. Shrooms Agents puts those sessions on your phone and in Basecamp: you see the reply as it is written, allow what it wants to run, answer its questions, send it a photo or a voice note.

shrooms is what makes that simple. Your machines are already on one mesh, so the phone reaches the laptop wherever both are — no port forwarding, no cloud relay, no account, no tunnel service. And the mesh is the lock: the agent listens only on mesh addresses, so only your own devices can reach it.

Install

On each machine that runs coding agents — shrooms already installed there:

curl -fsSLO https://raw.githubusercontent.com/vpavlin/shrooms/master/scripts/install-agent.sh
sudo bash install-agent.sh --voice

It runs the agent as you — never as root — and opens it to the mesh only; --voice adds voice notes (what it does).

On the phone, Shrooms Agents is an Android app beside shrooms — open it from the "agents" link in the shrooms app. In Basecamp, the shrooms_agents module. Neither is in a public store yet: AGENTS=1 scripts/build-apk.sh and make basecamp-agents-lgx.

1. What it does

Each machine runs shrooms-agent, which keeps that machine's sessions: a name, a directory, and the coding agent working in it. The phone app and the Basecamp module find every agent on your mesh and list their sessions together — the ones you star first, whatever machine they are on.

  • A conversation, streamed as it is written, in markdown, with each tool it uses folded to one line and its output folded below. It opens at the end, and search finds anything said in it — on the agent's machine, so it covers what the app has not loaded and what was said in a terminal before.
  • Permission prompts with the command in full and allow or deny — or auto-approve per session, the desktop's --dangerously-skip-permissions. Questions the agent asks come as a card with the options to pick, or room for your own words.
  • Files and voice notes. A photo or a log goes to the agent's machine and is named in your next message. A voice note is recorded on your device and transcribed on the agent's machine, by Parakeet through whisper.cpp — Czech and English and twenty-odd other languages, without saying which, and no audio reaches a speech service.
  • Taking over a terminal's conversation: a Claude Code session started in a terminal (or tmux) can be continued from the phone, in the same conversation.
  • Notifications on the phone when a session needs you or has replied, and context use, model and cost on every session.

2. Claude Code, pi, and the next one

The coding agent itself is pluggable. Two are built in:

  • Claude Code, driven the way its own SDK drives it. Everything above works with it.
  • pi, in its RPC mode, on whatever model pi is set up with — a model on your own hardware included, which is the point: a machine with no Claude account can serve sessions to the whole mesh. pi runs its tools without asking, so there is nothing to approve; its extensions' dialogs arrive as questions.

Adding another is one translator: a file that starts the program and turns what it says into the events the apps already show, so neither app changes. The guide walks through pi as the worked example, with the exact events a new one must produce. OpenCode and Codex are next; they are not built yet.

3. The access control is the mesh

shrooms-agent listens only on the machine's mesh addresses — never on its LAN or public ones — so the only devices that can reach it are your mesh's members. There is no account, no token, no server in the middle, and nothing to log in to: being admitted to the mesh is the authorisation, and revoking a device from the mesh revokes it here too.

What that means, said plainly. Every member of the mesh can drive the agents on it, and an agent can do whatever its user can do on that machine. That is right for a mesh of your own devices, which is what this is for. It is not right for a mesh you share with other people — run the agent only where every member is you.

The agent runs as an ordinary user, never as root, and is a separate program from the shrooms daemon: the network stays the boring, privileged part, and the part that runs code on request stays out of it.

4. What the installer does

install-agent.sh is run with sudo by the person whose agents it serves (--user NAME otherwise), on a machine where shrooms is running:

  • it copies shrooms-agent out of its own small image, ghcr.io/vpavlin/shrooms-agent — one static binary, for amd64 and arm64 — with the docker or podman shrooms already uses;
  • it lets you read the shrooms control socket, by a file ACL that survives reboots, if you cannot already;
  • it opens port 7387 to this machine's own mesh addresses only, when firewalld or ufw is running;
  • it installs the agent as your user service and keeps it running while you are logged out;
  • with --voice it builds whisper.cpp's parakeet-cli and fetches the model, checked by its hash.

It installs neither Claude Code nor pi: those are yours, logged in and set up as in a terminal, and the agent serves whichever it finds. --uninstall removes all of it but your sessions.

5. What it does not do

  • It cannot log a machine's agent in. Claude Code is logged in once on the machine itself; the app has no way to do it for you (why, and what could).
  • No terminal. It speaks to the agent, not to a shell; slash commands of the terminal UI do not exist here.
  • Takeover is Claude Code's only, so far.
  • One person's devices. As above: the mesh is the access control, so a shared mesh is the wrong place for it.
